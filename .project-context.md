# RiskFlow Projekt-Kontext & Richtlinien (v2 - Refined)

Dieses Dokument ist die zentrale Wissensbasis für die Entwicklung von RiskFlow. Alle Änderungen an Design, Architektur und Logik müssen diesen verbindlichen Regeln folgen.

## 🚀 Kern-Mission
RiskFlow ist eine **Mobile-First PWA** für Gefährdungsbeurteilungen. Sie ermöglicht Fachkräften für Arbeitssicherheit die Dokumentation direkt am Einsatzort (Offline-First).

## 🛠 Tech-Stack
- **Sprache:** Modernes Vanilla JavaScript (ES Modules).
- **Styling:** CSS3 mit Custom Properties (Variablen in `src/css/base/_variables.css`).
- **Storage:** Local-First via IndexedDB (`idb`-Library).
- **Build-Tool:** Vite.
- **PWA:** Service Worker für vollständige Offline-Fähigkeit.

## 🏗 Architektur-Standards (The RiskFlow Way)
- **Komponenten-Logik:** UI-Elemente werden funktional in `src/js/modules/ui/components.js` erstellt (z.B. `Button()`, `BetriebCard()`). Vermeide HTML-Strings direkt in der Geschäftslogik.
- **Zentralisierte Icons:** Alle SVGs leben ausschließlich im Dictionary `src/js/modules/ui/icons.js`.
- **Event Delegation:** Zentrale Click-Handler in `logic.js`. Identifikation über Klassen (z.B. `.btn-edit-betrieb`) statt über IDs, wo immer möglich.
- **Modulare CSS:** 7-1 Pattern (light). Jede View und Komponente hat ihr eigenes Stylesheet.

## 🎨 Design-System & UI-Richtlinien
- **Indigo-Design:** Primärfarbe `#4f46e5`. Nutze `Slate` für Texte und dezente Hintergründe.
- **Elevation:** Nutze das Schatten-System (`--shadow-sm` bis `--shadow-raised`) für Tiefe.
- **Typografie:**
    - KEINE reine Versalschrift (`ALL CAPS`) für Fließtext oder normale Labels.
    - Hierarchie über Font-Weight (700/800 für Titel) und Farbe (`--text-muted`).
- **Spacing:** Nutze die 8px-Skala (`--space-1` = 4px, `--space-2` = 8px, etc.).
- **Haptik:** Jedes interaktive Element braucht einen `:active { transform: scale(0.98); }` State.
- **Glassmorphism:** Header und fixierte Navigationselemente nutzen `backdrop-filter: blur(12px)`.

## 📱 Mobile-UX Patterns (Pflicht)
- **Bottom Navigation:** Hauptfunktionen sind über die fixierte Leiste unten erreichbar.
- **Modals & Dialoge:**
    - Desktop: Zentrierte Fenster.
    - Mobile: **Drill-Down Prinzip**. Listenansicht -> Klick -> Vollflächige Detailansicht mit "Zurück"-Button (`arrowLeft`) im Header.
- **Formular-Elemente:**
    - Nutze **Switches** (Toggles) anstatt Checkboxen für binäre Optionen.
    - Nutze **Custom Range Slider** für numerische Werte (z.B. Schriftgröße).
    - Nutze **Action Cards** (Icon + Titel + Button) für Datenbank-Aktionen.
- **Sichtbarkeit:** Steuerung über `.active` in Kombination mit `display: none !important`.

## 🧠 Logik-Regeln
- **Offline-First:** Jede Funktion muss ohne Internet funktionieren.
- **Sicherheit:** Nutze die `escapeHtml`-Funktion aus den UI-Komponenten für alle User-Inputs in Templates.
- **Wizard-Flow:** Komplexe Formulare (Beurteilungen) werden in logische Schritte unterteilt.
