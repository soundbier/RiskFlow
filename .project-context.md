# RiskFlow Projekt-Kontext & Richtlinien (v3 - Refined)

Dieses Dokument ist die zentrale Wissensbasis für die Entwicklung von RiskFlow. Alle Änderungen an Design, Architektur und Logik müssen diesen verbindlichen Regeln folgen.

## 🚀 Kern-Mission
RiskFlow ist eine **Mobile-First PWA** für Gefährdungsbeurteilungen. Sie ermöglicht Fachkräften für Arbeitssicherheit die Dokumentation direkt am Einsatzort (Offline-First).

## 🛠 Tech-Stack
- **Sprache:** Modernes Vanilla JavaScript (ES Modules).
- **Styling:** CSS3 mit Custom Properties (Variablen in `src/css/base/_variables.css`).
- **Storage:** Local-First via IndexedDB (`idb`-Library).
- **Build-Tool:** Vite.
- **PWA:** Service Worker für vollständige Offline-Fähigkeit.
- **Utilities:** `src/css/utilities/_display.css` für globale Sichtbarkeits-Logik.

## 🏗 Architektur-Standards (The RiskFlow Way)
- **Strikte Komponenten-Trennung:** UI-Elemente werden AUSSCHLIESSLICH funktional in `src/js/modules/ui/components.js` erstellt. Die Geschäftslogik (`logic.js`) darf keine HTML-Strings enthalten, sondern ruft Komponenten-Funktionen auf.
- **Zentralisierte Icons:** SVGs leben ausschließlich im Dictionary `src/js/modules/ui/icons.js`. Icons werden über den Key referenziert (z.B. `Icons.shield`).
- **Zentralisierte Utilities:** Hilfsfunktionen wie `escapeHtml` oder `setVisible` leben in `src/js/modules/utils.js`.
- **Sichtbarkeits-Steuerung:** Nutze NIEMALS `style.display`. Verwende stattdessen die CSS-Klasse `.hidden` in Kombination mit `utils.js#setVisible`.
- **Event Delegation:** Zentrale Click-Handler in `logic.js`. Identifikation über Klassen (z.B. `.btn-edit-betrieb`) oder Daten-Attribute (`data-id`).

## 🎨 Design-System & UI-Richtlinien
- **Indigo-Design:** Primärfarbe `#4f46e5`. Nutze `Slate` für Texte und dezente Hintergründe.
- **Elevation:** Nutze das Schatten-System (`--shadow-sm` bis `--shadow-raised`).
- **Typografie:** Keine reine Versalschrift (`ALL CAPS`) für Fließtext. Hierarchie über Font-Weight und Farbe (`--text-muted`).
- **Haptik:** Jedes interaktive Element braucht einen `:active { transform: scale(0.98); }` State.
- **Glassmorphism:** Header und fixierte Navigationselemente nutzen `backdrop-filter: blur(12px)`.

## 📱 Mobile-UX Patterns (Pflicht)
- **Bottom Navigation:** Hauptfunktionen sind über die fixierte Leiste unten erreichbar (nur in der Hauptansicht aktiv).
- **Drill-Down Prinzip:** Mobile-Ansichten (z.B. Einstellungen) nutzen das Drill-Down Prinzip. Klick auf Item -> Vollflächiges Panel mit `arrowLeft`-Button im Header.
- **Formular-Elemente:**
    - Nutze **Switches** (Toggles) für binäre Optionen.
    - Nutze **Custom Range Slider** für numerische Werte.
- **Wizard-Flow:** Komplexe Formulare (Beurteilungen) werden in logische Schritte unterteilt (`WizardHeader` Komponente).

## 🧠 Logik-Regeln
- **Offline-First:** Jede Funktion muss ohne Internet funktionieren.
- **Security:** JEDER User-Input muss beim Rendern über `escapeHtml` abgesichert werden.
- **State-Sync:** Nach Speicher-Aktionen wird die Liste (`renderTable`) und das Grid (`updateBetriebeGrid`) sofort aktualisiert.
